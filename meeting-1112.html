가진 옷 한 벌에서 시작하는 코디, 그리고 사람의 의견

오늘 회의에서 정리된 내용입니다. 타깃에서 성별을 빼고, 메인 기능을 매칭과 소셜 두 개로 좁혔으며, 데모는 API 없이 정해진 결과로 만들기로 했습니다.

Decisions

정해진 것

문제
가진 옷과 어울리는 새 옷을 찾고 싶은데, 원하는 걸 말로 표현하지 못해 검색이 실패한다.
페르소나
Jun, 27세. 변화가 필요해진 계기가 있는 사람. 성별은 두지 않고 앱에서도 묻지 않는다.
메인 기능
두 개. 사진을 올리면 어울리는 착장을 골라 주는 매칭, 그리고 다른 사용자의 의견을 받는 소셜.
온보딩
카드를 한 장씩 스와이프. 결과는 스타일 이름과 스케일 바, "You look great in …" 한 줄.
차별점
비슷한 옷이 아니라 같이 입을 옷. 그중에서도 한 단계 밀어 주는 One step up.
범위 밖
비슷한 상품 찾기는 지금 넣지 않는다. 확장 가능하다고만 적는다.
수익
제휴 링크 수수료로 시작. 유저는 무료. 이후 AI 매칭 횟수 제한(예: 주 3회)과 구독.
데모
API 없이 모든 경우에 정해진 결과. 결과 이미지는 얼굴 없는 마네킹으로 해 본다.
피치덱
YC 스타일로 단순하게. 제품 이해를 맞춘 뒤 마지막에 만든다.
작업 방식
Lovable이 느려서 코드를 GitHub로 가져와 로컬에서 고치고, 확인되면 Lovable에 반영한다.

일정

  1. 오늘 회의 중제품 이해 맞추기다섯 명이 같은 그림을 보도록.
  2. 오늘 저녁MVP와 기본 자료앱은 8시쯤, 수정은 10~11시까지.
  3. 금 11/13 아침최종 덱제출 마감 13:45, Hack Fair 14:00.

화면별로 바꿀 것

수정된 Pairly 빌드를 같이 보면서 나온 피드백입니다. 아직 빌드에 반영되지 않았습니다.

화면바꿀 것
Upload사진을 올린 뒤에는 "Snap one piece you already own" 문구를 지운다.
Upload아이템 이름과 태그(Navy, Wool, Tailored)를 지운다. 내부 데이터라 보여 줄 필요가 없다.
Upload"What's the occasion?"으로 묻고 칩은 유지한다.
Upload"What items would you like to be matched with?"를 추가한다. 복수 선택.
Upload"Anything else?"를 "Describe the vibe you're going for"로. 예시는 "Gallery owner in Paris at a formal dinner".
Results제목 "3 ways to wear it"을 바꾼다. 매칭 아이템을 추천한다는 느낌으로.
ResultsSafe / One step up / Bold는 "도전하고 싶은 정도를 고르세요" 같은 안내로 보여 준다.
Results착장 이미지는 마네킹에 내 옷과 추천 아이템을 입힌 모습으로.
ResultsGet feedback 버튼을 지운다. AI가 추천한 착장을 그대로 올려 의견을 받는 건 어색하다.
Social"This week's trends"와 "Top rated this week"를 지우고, 그 자리에 Your post를 둔다.
SocialRate the fit 아래에 댓글 기능을 넣는다.
Social의견은 + 버튼으로 내 착장 사진을 직접 올려서 받는다. 샘플 사진은 데모용으로 둔다.
Saved"Find matches" 버튼을 지우고 더미 아이템 몇 개를 넣는다.
Saved아이템뿐 아니라 착장 전체도 저장한다. 내가 올린 옷도 자동으로 저장해 다시 찍지 않게 한다.

할 일

  1. 위 화면별 변경을 Pairly에 반영하기 (GitHub 연결 뒤 로컬에서).
  2. 퀴즈 결과 16가지에 맞는 룩 사진 구하기. 4개쯤은 사람이 고르고 나머지는 AI로 생성.
  3. 팀원 한 명의 유형을 골라 그 유형 하나는 끝까지 제대로 만들기.
  4. 상품 20개 정도를 골라 쇼핑 링크 걸기.
  5. 피치덱에 들어갈 자료 모으기: 왜 시장의 문제인지, 스타일을 고를 때 어떤 요소를 보는지.
  6. 남성 사용자 인터뷰로 근거 모으기. 아직 사용자 근거가 없다.

아직 정하지 않은 것

역할

MVP 1~2명, 피치덱, 자료조사를 누가 맡을지. 덱은 한 사람이 리드하자는 의견이 있었다.

제품 이름

Pairly가 "나쁘지 않다"는 반응. 확정은 아니다.

퀴즈 카드 수

12장 유지 또는 유형당 1장씩 16장. 유형 이름 12개도 초안 상태다.

구현 범위

16유형을 모두 채울지, 몇 개만 구현하고 나머지는 덱에서 설명할지.

피드백 기능

나온 아이디어: 응원과 비평 중 고르기, AI가 악의적인 댓글 거르기, AI가 댓글을 모아 원하는 말투로 요약하기.

입력 방식

텍스트와 음성 중 무엇으로 받을지. 지금 빌드는 텍스트다.

이번 회의에서 바뀐 점

  • 타깃: 20~30대 남성 → 성별 없음. 질문을 받으면 "팀 안에서도 서로 너무 달랐다. 이렇게 시작하고 트랙션이 생기는 쪽으로 간다"고 답한다.
  • 소셜: 11/11에는 뺐지만 오늘 다시 넣었다. AI 추천만으로는 불안하다는 점을 사람의 의견이 채운다.
  • 온보딩: 둘 중 하나 고르기 → 카드 스와이프. 결과는 4글자 코드 대신 이름과 스케일.
  • 추천 결과: 아이템 하나 → 착장 전체. 옷 하나만 보면 전체 모습이 그려지지 않는다.
